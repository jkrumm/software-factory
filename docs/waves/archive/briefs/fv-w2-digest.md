# Brief: FV Wave 2, the digest

Read `AGENTS.md`, `docs/waves/fv.md` (the lead's decisions, Wave 2), `docs/research/2026-11-01-fleet-view.md` ("The digest run"), `docs/design.md` §11 "The fleet view" (Wave 1 as built) and `packages/server/src/fleet/` first, and `agw digest --help` on the mini plus agent-workflows `packages/host/src/workflows/digest/README.md` (the capability is live: items `{id, kind: heading|session|reply|window, text, context?}`, at most 64, one model call; answers per id; a failed item comes back as `error`). The factory calls agw like any client (SF2: the factory never calls a model itself), the way `issues/classify` calls `agw factory-classify`: read that code for the call, its timeout and its failure path.

1. **Fingerprints, then one call.** Every 5 minutes (`FACTORY_DIGEST_EVERY`, off with `off`), after a snapshot build: an item is a plan heading without `<!-- short: … -->`, a live session (its headline), and the last assistant reply of a session whose turn count moved (reply extract). Each item's fingerprint is the content it would send. Unchanged since its cached answer: nothing. The changed ones, at most 64, go to **one** `agw digest` call, off the tick and outside any transaction; more than 64 wait for the next pass, oldest first.
2. **IuRoot never goes.** No item from a repo, plan or session marked `visible` is ever sent: their `short` stays the plan's own comment or the heading cut at 8 words, their `headline` null. A test pins it with an IuRoot session whose reply asks something.
3. **The cache:** `factory.fleet_digest (key text primary key, fingerprint, answer jsonb, at)` keyed by item; the snapshot reads it, so `short`, `headline` and reply asks appear in `/fleet` from the next build. A heading's short is made once per heading text; a headline at most once per new turn.
4. **Reply extract:** the reply is read from the session's transcript (`transcript_path`, the last assistant text, bounded, read as data); an answer with `asks: true` and confidence high or medium joins `asks` with `source: "reply"`, its `kind` and `short`, id `reply:<session>:<turn>`. A newer turn of that session replaces it.
5. **Failure is quiet:** a failed or slow call (timeout 60 s) leaves the model as it was; `factory status` gets one line with the count of failed passes in the last day; the spend per day (agw's answer carries the cost) is in `factory fleet --format json` under `digest`.
6. **Tests** with a fake agw (a script on `PATH`, as classify's tests do): one call per pass, unchanged items cost nothing, more than 64 wait, a failed call keeps the model, the cache survives a restart, IuRoot never sent.

**Gate:** `make check` green, `/review` with findings fixed, one more `/review` pass on the fix commits. **Wait for every review run in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead.
