# Brief: FV Wave 1, the fleet read model

Read `AGENTS.md`, `docs/waves/fv.md` (the plan, the lead's decisions, Wave 1), `docs/research/2026-11-01-fleet-view.md` ("The read model", "Asks: where they come from"), `docs/design.md` §2 and §11, `packages/server/src/status.ts` and `packages/server/src/projects/` (how git and files are read off the tick, bounded, outside transactions) first.

1. **Contract and API:** `packages/contract/src/fleet.ts` is the proposal's shape (`summary`, `asks[]`, `repos[]` with `plan` and `sessions[]`, `quota`, `queue`), zod, strict. `short`, `headline` and `suggestion` exist and are null in this wave. `GET /fleet` on the token API and the socket; `factory fleet [--format json|plain]` (plain fits one screen: asks first, then repos with a running plan). A Postgres `NOTIFY fleet` with the new fingerprint when the model changes.
2. **A snapshot, built off the tick:** every 30 s and on demand, one builder reads everything outside any transaction (bounded git and file reads as `projects/` does) and stores the result in one row (`factory.fleet_snapshot`: the JSON, its fingerprint, built_at). `GET /fleet` answers from that row, never builds inline. A failed source leaves its part as it was with an `errors[]` line; the rest stands.
3. **Repos:** every git repo directly under `FACTORY_REPO_ROOTS` and `FACTORY_VISIBLE_ROOTS` (new, default `~/IuRoot`) that has a plan or a live session; branch, dirty, last commit. A repo under a visible-only root is marked `visible: true` and is never a spawn or Issue target (the existing repo-roots checks stay as they are).
4. **Plans:** a session's plan from its spawn's prompt when it names a `docs/waves/*.md` path, else the repo's `docs/waves/PLAN.md`, plus any plan a live spawn names outside it (the teamchat case: `prometheus-scripts/wip/…/docs/waves/PLAN.md`). Headings `## Wave <n> — <title>`, `<!-- short: … -->`, statuses with optional date and text (`<!-- status: done 2026-11-01, release … -->`); states `running|planned|scheduled|stale|done` by the proposal's rules, `lastTouched` from git (the plan file's last commit).
5. **Sessions:** the factory's sessions and hc's terminals (`hc ls --json`) merged by name, IuRoot's included: role, parent, state, wait, account, terminal, Claude's tab title, since, lastActivityAt.
6. **Asks, deterministic only:** hc `blocked` and `wait=owner`; the factory's attention lines and failed notifications; open `decisions`; the human queue through `ask-human.sh list --json` (dotfiles adds it in parallel; until it exists the source is an `errors[]` line, not a crash; path from `FACTORY_ASK_HUMAN`, default `~/SourceRoot/dotfiles/scripts/ask-human.sh`). Each ask has a stable id (`<source>:<key>`), `kind`, `repo`, `session?`, `text` as data, `at`.
7. **Tests** through the API and the CLI, with a recorded fixture of a real estate: plans with dated statuses, a stale plan, an IuRoot session, a failing source. No IuRoot text leaves the mini: assert that nothing in this wave calls agw.

**Gate:** `make check` green, `/review` with findings fixed, one more `/review` pass on the fix commits. **Wait for every review run in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead. Push the branch, open a PR (`gh pr create`, no attribution), don't merge or deploy. End with a report: done / deferred, one line each.
