# Brief: F2 Wave 6, the two F2 gamedays

Read `AGENTS.md`, `docs/waves/f2.md` (Wave 6), `docs/design.md` §5 ("Following a lead", "Done means evidence") and §13, and `scripts/gameday/` (F1's, live against the deployed factory: `lib.sh`, `setup.sh`, `teardown.sh`, `template/`) first. The three real requests of the gate are the lead's, not yours.

Both run **live against the deployed factory**, with real leads, on scratch repos made like `setup.sh` makes one (a repo under `~/SourceRoot` with a local bare remote, the `.git/factory-gameday` marker, a `project.yaml` v0, `deploy.mode make`, `hold: 1m`; `teardown.sh` removes it). Reuse `lib.sh` (`fx`, `db`, `log`, `scrub`); evidence goes to `docs/evidence/f2-gate/<gameday>/` (`GAMEDAY_EVIDENCE`) and carries no home directory, host, address or token. Nobody types into a lead's pane during a run: the script files the Issue and reads the database, and that is all it does. Keep each lead small: the ask is short and the repo tiny, so one run costs minutes of the cheapest tier.

1. **`silent-lead.sh`:** an Issue whose ask makes the lead end its turn without one factory verb, on every turn. Pass: the first unreported stop is sent back with one line (the `events` row and the prompt id), the second parks the Issue (`waiting` or the state §5 says, with the line for the owner, a `notify:parked` row in `factory.notifications`), the claim is held as the machine says, nothing else happened. Then `factory issue stop` ends it and finalize removes tab, worktree and claim.
2. **`seeded-bug.sh`:** the scratch repo has a real small program, `make check` green, `make deploy` copies it to a directory outside the repo, `make verify` runs the deployed copy. The seeded bug: the repo ships a change-independent fault that only the deployed copy shows, a value read from the deployed directory's own config that `make check` never reads, so a correct lead ships green. The ask is one harmless real change. Pass: the lead ships with its evidence, the Issue is `watching`, and inside the hold the bug bites: either the production check the lead runs catches it, or `make verify` after the hold moves the Issue back to `working` with a note to the **same** lead (same session, same attempt's worktree; `notify:regression` row). The lead fixes it, ships again, the second hold is green, the Issue closes, finalize runs once, the transcript is in the archive. Run it through the full loop, close included.
3. **`run.sh`** runs one or both, writes `report.md` per gameday: the timeline from `events` and the inbox, pass or fail per line of the pass condition, wall time, the lead's tier, effort and account.

A run that fails a pass line is a finding, not a retry: keep its evidence, report it, and a rerun gets a new run id. At most three runs per gameday. `factory quota get` before each; if `me2` is past 60 % of its week or `iu` past 90 %, stop and report.

**Gate:** `shellcheck` clean on the new scripts, `make check` green, both gamedays passed or their findings reported with evidence, `/review` with findings fixed, one more pass on the fix commits. **Wait for every review run and every gameday in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead. Push the branch, open a PR (`gh pr create`, no attribution), don't merge. End with a report: done / deferred, one line each, and one line per pass condition with its evidence path.
