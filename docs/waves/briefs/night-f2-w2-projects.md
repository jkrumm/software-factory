# Brief: F2 Wave 2, `project.yaml` v0 and claims

Read `AGENTS.md`, `docs/waves/f2.md` (Wave 2), `docs/design.md` §4 (Claims), §9, §12, and `packages/server/src/issues/` (Wave 1, live) first. The steps are Wave 2 of `f2.md`.

1. **The v0 schema** (zod, `packages/contract/src/projects.ts`, YAML parsed with a pinned dependency, check it with `/research`, never from memory; exact pin, the release-age cooldown applies): `apiVersion: factory/v2`, `name`,
   `deploy { mode: auto|make|agentic|none, targets[{ name, host, verify }], hold (duration, default 30m), migrations[], probes[{ name, http, expect }] }`, `ship[{ paths[], via: push|pr }]` (first match wins, `paths` are globs), `leads` (default 1). Later keys
   (`signals`, `heal`, `jobs`, `ticktick`) are accepted and ignored, so an F3 manifest does not break F2. No manifest = defaults: requests only, one lead, `deploy.mode none`, ship by the repo's `pr-required-repos` default of `push`, done means the commit or the document.
2. **Sync:** every repo directly under a `FACTORY_REPO_ROOTS` root that has a `project.yaml` on its checked-out default branch, and every repo an Issue or spawn names, gets a `factory.projects` row keyed by the directory's name (the slug `usage` uses, U4; two roots with the same name: the key is `<name>` for the first and the full path decides, say how you settled it in the design). On a tick at most every 10 minutes and on demand (`factory project sync`). Reading a file is not a port call that can hang a transaction, but keep it outside one all the same. A manifest that does not parse keeps the last valid version and opens **one** upkeep Issue through `createIssue` (`source: "upkeep"`, `source_key` `manifest:<project>:<sha256 of the content>`).
3. **Claims:** `repo:<name>` admits `leads` (default 1) plus one urgent. A spawn with an `issue_id` waits on its claim like any hold (`hold: "claim"`, re-checked like `pace`, no account reserved). Fleet spawns without an Issue (waves, fan workers, `rd`) take no claim: F1's behaviour is unchanged. A claim is released by finalize (Wave 4); until then the Issue's terminal transition releases it, written so Wave 4 can move it.
   The table `claims` is §12's. Promotion is "the oldest queued Issue goes first". `factory status` shows the hold reason.
4. **The make contract check:** which of `check|test|deploy|verify|restart|quality|logs|status` each project has (`make -pn` or a parse of `.PHONY`/rules, with a process timeout, with `childEnv()`), stored on the row, shown by `factory project show <name>`. `factory project list`.
5. **Manifests:** this repo (`deploy.mode: make`, `verify` through `make verify`, `hold: 30m`, `ship: [{ paths: ["**"], via: pr }]`, no public hostnames) and two others the owner ships often. Pick from the last 30 days' commit volume across `~/SourceRoot/*` (say which and with what numbers), both with a `make deploy` or an automatic deploy; not `homelab-private`, no repo under `~/IuRoot`. They must be public-safe: no hostnames or IPs in a tracked file, `probes` use the placeholder form only if the repo already publishes that URL.

Tests through the public surface: a valid manifest, a broken one (one Issue, last valid kept, a second sync with the same content opens none, a changed broken content opens a second), no manifest, the claim holding a second lead and admitting the urgent one, a fleet spawn untouched, the make contract on a fixture Makefile.

**Gate:** `make check` green, `/review` with findings fixed, one more `/review` pass on the fix commits. **Wait for every review run in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead. Push the branch, open a PR (`gh pr create`, no attribution), don't merge or deploy. End with a report: done / deferred, one line each, and the two repos you picked.
