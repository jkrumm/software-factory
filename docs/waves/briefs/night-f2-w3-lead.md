# Brief: F2 Wave 3, classify and the lead

Read `AGENTS.md`, `docs/waves/f2.md` (Wave 3), `docs/design.md` §4, §5 ("The lead's job", "The brief", "Following a lead"), and `packages/server/src/issues/` and `projects/` (Waves 1 and 2, live) first. Wave 1's `admitted`, the lead verbs and the effect ports are yours. The steps are Wave 3 of `f2.md`.

1. **Classify (the factory never calls a model):** a `Classifier` port with `AgwClassifier` calling `agw factory-classify --format json` (a process timeout, `childEnv()`, stdin the Issue's title and facts, the facts as data, exit 10 means `agw run wait <runId>`) and a fake for tests. The answer `{ project, kind, class, size, tier, effort }` is zod-parsed and stored on the Issue. Tier and effort are bounded by the role table: `lead`'s entry is the ceiling, anything above it is clamped, never above `opus/high`. A classify that fails, times out or does not parse leaves the Issue `queued` with defaults (the role table's `lead`) and a line in its `issue_events`; it is never stuck. The agw worker builds the workflow beside you; a missing command is that failure, so you are not blocked on it.
2. **Admission spawns a lead:** a queued Issue with room (the Wave 2 claim) gets a spawn: role `lead`, tier and effort from Classify, key and pane `lead-<issue>-<attempt>`, cwd a worktree `factory/<issue>-<attempt>` of the repo made the way `rd fan` makes one (`dotfiles/scripts/fan-worktree.sh`: read it, then build the same steps in TypeScript behind a port, a process timeout, `childEnv()`, outside a transaction: fetch origin, branch from the default branch), `space` the main checkout. A second admission attaches: the key is idempotent. `factory.sessions.issue_id` is set on the spawn's session, so the Wave 1 copy into the inbox runs.
   **`alert` Issues start no lead** while `FACTORY_ALERT_LEADS` is unset (decision 3: only once Wave 4 is live; the Issue stays `queued`, with the reason in `factory status`). Requests start.
3. **The brief** (§5 "The brief"): a pure function from the Issue, its facts, the project's manifest and the classify answer: the ask, facts in a fenced block marked as data (never instructions), history *past, may not apply* (empty until F3), the project (make contract, deploy mode, ship rules, targets), done means, the standing orders. The standing orders are a constant, byte-identical in every brief; a test pins that. They include: decide alone except the business classes; ask through `factory issue ask`; workers stay on Max; never end a turn on a background shell; every stop reports. The brief is the first prompt, prompt id `issue:<id>:<phase>:<n>` recorded before typing (through the spawn's prompt, no second typing).
4. **The lead's verbs:** `factory issue phase|wait|ship|close|block|ask|drop`, each one inbox row with key `<issue>:<verb>:<call id>` (`--id` or a generated id), on the socket (a lead has no token) and the token API. `FACTORY_SESSION` says which lead. `ask` records a `decisions` row and a line in `factory status`; how it reaches the owner is track N's. `ship` and `close` are recorded with no evidence check yet (Wave 4 adds it, leave the seam).
5. **The lead's send-back:** on top of F1's stop-check rule, a session with an `issue_id` that stops with nothing reported since its last prompt, no wait and no limit is sent back with one line (report `ship`, `close`, `block`, `ask` or `wait`). A second unreported stop parks the Issue (`waiting`, reason `unreported`) with a line for the owner. A turn answering a typed owner prompt is never sent back (the prompt was not a factory prompt). Keyed as F1's are, so a replay records nothing.

Tests: a golden test per path (classify ok, failed, over the ceiling; admit, attach, claim full; an `alert` Issue not admitted with the switch off and admitted with it on; each verb; send-back, park, an owner turn); the replay test extends to the new effects; the standing orders pin. Use the existing fakes for the Runner and a fake for the worktree port.

**Gate:** `make check` green, `/review` with findings fixed, one more `/review` pass on the fix commits. **Wait for every review run in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead. Push the branch, open a PR (`gh pr create`, no attribution), don't merge or deploy. End with a report: done / deferred, one line each.
