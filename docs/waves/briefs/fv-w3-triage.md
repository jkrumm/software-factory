# Brief: FV Wave 3, triage and actions

Read `AGENTS.md`, `docs/waves/fv.md` (Wave 3), `docs/research/2026-11-01-fleet-view.md` ("Triage: four tiers"), `docs/design.md` §2 (writes from any surface are intents) and §11 "The fleet view" (Waves 1 and 2 as built), and `packages/server/src/fleet/` first. The human queue's `ask-human.sh resolve <id> --as done|denied|superseded [--note]` lands in dotfiles beside you (a worker there); until it exists the queue's actions answer 503 with the reason.

1. **A tier per ask:** `automatic | one_click | hand_off | yours`, by deterministic rules first: the business classes (spend, irreversible data loss, Touch ID or a machine the owner must be at, other people) are `yours`; a request older than 7 days whose command names a thing a probe shows done or absent is `one_click`. The model (Wave 2's digest) only ranks within a tier; it never moves an ask into `automatic`.
2. **Suggestions with evidence:** `suggestion { verb, why, evidence, confidence }`. Probes are read-only and bounded, run off the tick: a path exists or not, an app is installed or not (`/Applications/<name>.app` on the machine named), a newer deploy of the same repo exists (git), a plan is 10/10 done. A suggestion without evidence is not shown.
3. **Actions are intents:** `POST /fleet/asks/:id/act {intent, note?}` (token only, like `/fleet`): `resolve` (queue: `resolve --as done`), `deny` (queue: `--as denied`; a decision: `factory issue answer` with the denial), `later` (a timer of its own, the ask hidden until then), `archive_plan` (a done plan: one commit moving it to `docs/waves/archive/`, made by a spawned worker, never by the server), `hand_off` (an `rd fan`-equivalent spawn with a brief built from the ask, its result comes back as a new ask). The `yours` tier offers only `later` and `deny`. An old queue request is denied, never run with its stale command.
4. **The automatic tier is bookkeeping only:** marking a plan stale, folding an ask under the newer ask that supersedes it, dismissing an expired note. Each is a row in `factory.fleet_triage_log` (what, why, evidence, at, undone_at) and undoable (`POST /fleet/triage/:id/undo`). It never runs a command and never denies.
5. `factory fleet act <ask> <intent> [--note]`, `factory fleet triage [--undo <id>]`; `/fleet` carries `tier`, `suggestion`, `actions[]` per ask.
6. Tests through the API: a business-class ask offers only later and deny; an automatic step and its undo; a hand-off spawn; a stale queue request suggested as deny with its evidence; nothing in this wave runs a request's command.

**Gate:** `make check` green, `/review` with findings fixed, one more `/review` pass on the fix commits. **Wait for every review run in the foreground** (`agw run wait <runId>`): never end a turn while a background shell runs, the factory reads your idle prompt as finished and wakes the lead. Push the branch, open a PR (`gh pr create`, no attribution), don't merge or deploy. End with a report: done / deferred, one line each.
