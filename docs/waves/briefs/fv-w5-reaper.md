# Brief: FV Wave 5, the reaper

Read `AGENTS.md`, `docs/waves/fv.md` (Wave 5, the reaper item: the owner's remark of 2026-11-02), `docs/design.md` §3 "As built" (the runner, placement, the witness) and §11 "The fleet view" (Waves 1 to 4 as built: the triage log is the "Handled for you" group), `packages/server/src/fleet/` and the `Runner` port first.

1. **Who is closed: all of these, checked in the build (off the tick, bounded git, no transaction around a port):**
   - a Claude Code session in an hc terminal whose `cwd` is a worktree (`<repo>/.claude/worktrees/<name>`) of a repo under `FACTORY_REPO_ROOTS`; **never** a repo's main checkout, never anything under `FACTORY_VISIBLE_ROOTS` (IuRoot is read-only: shown, never acted on), never a session of an open Issue;
   - idle at least 2 h: no turn and no hook event for 2 h and the agent not working (hc status and the derived state agree);
   - its worktree clean: `git status --porcelain` empty, untracked files included;
   - its branch merged into the repo's default branch (by commit, or by content: `git cherry` or the branch's tree equal to a commit on the default branch's first-parent line) or gone with its commits on the default branch; a branch with a commit the default branch lacks is **unmerged** and never closed;
   - its parent waits on nothing of it: no parent, a parent that is gone, or a parent not in `wait=workers` (a parent waiting on workers may still send it fixes).
2. **What closing is:** `hc kill`, then `hc rm` (the runner's port gains a `close` if it has none), and the app's tab cleanup if herdr-core has a call for it (look in `hc --help` and the OpenRPC API, dotfiles `docs/herdr-core.md`; if there is none, kill and rm only, and say so in the report). The worktree stays (`rd fan --clean` owns worktrees). One row per close in `fleet_triage_log` (kind `reaped`, what, why, evidence: idle since, the merge proof, the parent's state), so it shows under "Handled for you" and in the morning reading as one line. Not undoable: the log says so.
3. **What is listed, never closed:** sessions idle 2 h with an unmerged branch or a dirty worktree: `/fleet` gains `reaper { closed: [...] (last 24 h), kept: [{session, repo, why}] }`; `kept` items are no asks (no push).
4. **The switch:** `FACTORY_REAPER=on|dry|off` (default `dry`; `env-file.sh`'s allowlist gains it): `dry` writes the would-close list into `reaper.closed` marked `dry` and closes nothing. At most 5 closes per pass; a close that fails is a line in `errors` and retried next pass, never a loop.
5.
