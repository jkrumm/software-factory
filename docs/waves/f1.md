# F1: the fleet layer

**Goal:** the factory server runs on the mini and babysits every `rd`/`/wave` session deterministically: hook events,
derived state, a queue with capacity and `run|pace|drain`, the rules that act, and `rd` as its client. FL1–FL8 of
`docs/decisions.md` hold, and `wave-watch.sh` polling, `fleet-keepalive.sh` and the Hermes babysitter cron are retired.
**Gate:** per wave, `make check` green on the merged head, `/review` clean or every finding answered, landed with
`rd merge`; from Wave 1 on also `make deploy` and `make verify` live on the mini. The track's gate (Wave 6): an
overnight multi-wave run across two repos with an injected limit wall and one `drain` needs no owner "continue".

Design: `docs/design.md` §2 and §3. Evidence: `docs/program.md` F1 notes, `docs/research/2026-10-30-claude-code-unattended.md`.

**Tooling.** oxlint and oxfmt, not Biome (owner, 2026-10-30; track T swaps the skeleton after Wave 3 lands). Briefs from
Wave 4 on say so.

**How this plan runs.** This repo's `docs/waves/PLAN.md` holds the program lead's rotations, so F1's waves are not
`rd wave`s here. Each wave is one `rd fan` worker (Sonnet, brief from the skill's `roles/worker.md`) in a worktree of
this repo, landed by the program lead with `rd merge`; a wave's dotfiles part is a second worker in dotfiles, on
disjoint files. The program lead ticks this file and writes **Left behind** after each merge. One wave at a time:
the waves share `packages/server`.
