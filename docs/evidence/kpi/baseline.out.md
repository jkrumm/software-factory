## Data quality and caveats

- Snapshot taken 2026-10-22T07:51:56Z, 8 min before AS_OF; latest transition 2026-10-22T07:33:03Z, latest row update 2026-10-22T07:43:08Z. Nothing after AS_OF was read.
- The transition log starts 2026-09-09T19:43:30Z. 90 rows (created 2026-09-08 to 2026-09-14) have no creation transition and 33 have no transitions at all (closed 9, quiet 24); their escalations and touches before the log are invisible. Only the `all` window is affected; 14d and 30d start after the log.
- Round 5's `finished unattended` (201 of 368) is the same idea as `autonomy_rate`, minus the owner:/cli: operations; it never checked that an item had finished.
- `close_reason` is cleared when an item leaves `closed`, so 95 earlier closures have their reason inferred from the note (attached to #N = duplicate, fixed by = fixed_by, ignore-list or abort or empty note = ignored, everything else = resolved).
- `signature` is unique per row (597 distinct of 597); `fixed_by_pr` is populated on 0 rows although one item closed as `fixed_by`; `revert_pr`/`reverting_sha` on 0; 9 items with a done merge operation have a null `merged_sha`.
- 3 `operations` rows are authorised by `owner:` or `cli:`; the 1 without an event id cannot be tied to an item, so the item-level touch count misses it.
- `events.first_seen` moves forward when a signal recurs (52 rows), so time zero is min(events.first_seen, triage_items.first_seen, triage_items.created_at).
- 139 rows have no repo (unrouted signals).
