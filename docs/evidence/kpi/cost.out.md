## Data quality and caveats

- usage-tracker's `opencode` collector last stored a row at 2026-10-13T12:34:45.777Z while reporting `ok`. It reads `~/.local/share/opencode/opencode.db` (`usage-tracker/src/collectors/opencode.ts:31`, tables `session` and `message`); agent-gateway's OpenCode v2 server writes `~/.local/share/agent-gateway/opencode/opencode.db` (table `session_v2`, first session 2026-10-14T12:36:04Z). So usage.db, and anything built on it (Argo's `usage_record`), has no IU OpenCode session since 2026-10-13. This script reads the v2 store directly, which `snapshot.sh` does not freeze.
- 86 of 1662 jobs are unpriced: 14 created before the first priced job, 29 created in the opencode collector gap, 24 failed or cancelled without any usage row, 6 no usage row at all, 13 sessions row only. The `agent-gateway-sessions` rows name the backend and the turns but 0 of them carry tokens or cost, so a job with only those rows is unpriced.
- Jobs run in place (no worktree) cannot be matched by path and stay unpriced unless a windowed row falls on them; the same holds for any episode whose usage rows lack the worktree project.
- Pricing: usage-tracker `pricing.ts` and OpenCode v2's own `session_v2.cost` agree on Haiku 5.5 ($0.10 in, $0.50 out, $0.01 cache read, $0.125 cache write per million tokens); Max rows are list prices, so a Max figure is what the usage would cost on the API, not what was paid.
- Items that were never given a dispatch (quiet, ignored, duplicates) cost nothing here by construction; the numerator includes the cost of items that did not resolve (failed, ignored, still open), as the definition says.
